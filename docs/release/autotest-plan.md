# ゲーム内チェックリストの自動化の方針

`ingame-checklist.md` の項目を、どの方法で確かめるかの対応表です。自動テストを足したら、ここの表も直します。

## 方法

| 記号 | 方法 | 実行 | 判定 |
|---|---|---|---|
| A | サーバーのテスト（`src/gametest/.../server/ServerCases.java`）。画面なしのサーバーで、テストの区画に小さな村（ベッドと村人）を作り、仮のプレイヤーで交易所を置き、取引する | `autotest.bat server`、`build.bat gametest`（約1分） | 自動 |
| B | クライアントのテスト（`src/gametest/.../client/ClientChecklistTests.java`）。本物のクライアントでワールドを作り、キー操作・画面の操作をする | `autotest.bat client`（ゲームのウィンドウが開く。数分） | 自動 |
| C | B の中でスクリーンショットを撮る（`build/autotest/screenshots/`） | B と同じ | 人が画像を見る |
| 手 | 手で確認する（他の Mod・2人のプレイ・遊んだ感触・自然に生成された村など） | ― | 人 |

- 結果は `tools/checklist/record.js` がチェックリストの各行に書き込む（全部を確かめた項目は `[x]` と〔自動 ✔ 版 日付〕、一部だけなら〔一部自動 ✔ 版 日付：確かめた範囲〕、失敗は〔自動 ✘ 版 日付〕）。一覧は `autotest-report.md`
- A のテストは1つのゲームテストの中で順に実行する（同じバッチのゲームテストは同時に動き、市場はワールド全体で共有されるため）。各項目の前に市場・ブロック・エンティティ・仮のプレイヤーを消し、設定を既定に戻す
- Minecraft 標準の仮のプレイヤーはクリエイティブ固定なので、A ではサバイバルの仮プレイヤーを自分で作る（`ServerCtx.player`）
- 日数がかかる項目は、A の中で設定 `recovery.clock` を `DAY_TIME` にして時刻を進める。確率の項目は設定で確率を 1 にする
- 本体のコードにテスト専用の処理は足さない
