# ゲーム内チェックリストの自動化の方針

`ingame-checklist.md` の項目を、どの方法で確かめるかの対応表です。自動テストを足したら、ここの表も直します。

## 方法

| 記号 | 方法 | 実行 | 判定 |
|---|---|---|---|
| A | サーバーのテスト（`src/gametest/.../server/`）。画面なしのサーバーで、テストの区画に小さな村（ベッドと村人）を作り、仮のプレイヤーで交易所を置き、取引する | `autotest.bat server`、`build.bat gametest`（約1分） | 自動 |
| B | クライアントのテスト（`src/gametest/.../client/ClientChecklistTests.java`、ケースは `ClientTradeCases`・`ClientDisplayCases`・`ClientScreenCases`・`ClientStaffCases`・`ClientStaffMoreCases`・`ClientBankQuestCases`・`ClientTownCases`・`ClientBuySellCases`・`ClientItemCases`・`ClientSellAllCases`・`ClientBoardCases`・`ClientConfigCases` にも）。本物のクライアントを**日本語**で起動してワールドを作り、キーとマウスで操作する。専用サーバー（同じプロセスの中で起動）にも接続する | `autotest.bat client`（ゲームのウィンドウが開く。数分） | 自動 |
| B′ | Mod Menu・YACL を外したクライアント（`runClientGameTestMinimal`。jar はクラスパスに残るが、Fabric Loader の `fabric.debug.disableModIds` で読み込まない）。起動してタイトル画面が出ることだけを確かめる（`ak.autotest.minimal`） | `autotest.bat minimal`（約1分）。`autotest.bat` でも流れる | 自動 |
| C | B の中でスクリーンショットを撮る（`build/autotest/screenshots/`） | B と同じ | 人が画像を見る |
| 投稿用 | チェックリスト外。配布ページのスクリーンショット4枚（`PostScreenshots`、`runClientGameTestShots`、`ak.autotest.shots`）。決まったシード（`PostScreenshots.SEED`）の普通の世界で村の屋台を探し（無ければ屋台の建物を置く）、村の建物2つをその場で建て、ほかの市場3つと商会のニュース、価格の履歴を用意して、1920×1080・GUI と HUD を隠して撮る | `shots.bat`（約5分）。`release.bat` が呼ぶ | 人が画像を見る（`docs/release/Screenshot/auto/`） |
| 手 | 手で確認する（他の Mod・2人のプレイ・遊んだ感触・自然に生成された村など） | ― | 人 |

結果は `tools/checklist/record.js` がチェックリストの各行に書き込みます（全部を確かめた項目は `[x]` と〔自動 ✔ 版 日付〕、一部だけなら〔一部自動 ✔ 版 日付：確かめた範囲〕、失敗は〔自動 ✘ 版 日付：テスト名〕）。一覧は `autotest-report.md` です。

## テストの種類

| 種類 | 内容 | 場所 |
|---|---|---|
| 成功の流れ | 置ける・買える・売れる・値段が動く・レシピなど。所持金・持ち物・相場の変化と、仮のプレイヤーに届いたチャット（翻訳キー）と結果コード（`TradeResultS2C` など）で判定する | A `ServerCases`（章ごとに `ServerChapterCases`（お金と保存データ）・`ServerWorldCases`（品揃え・商人・コイン・市場名・置き場所・村人の取引）・`ServerReputationCases`（評判・商会・流行）・`ServerDevelopmentCases`（村の発展）・`ServerFacilityCases`（娯楽施設と建物8種の効果・港・見張り塔）・`ServerAdvancementCases`（進捗）・`ServerGoodsCases`（商品のデータ・掘り出し物）・`ServerDimensionCases`（ネザー・エンドの市場）） |
| 失敗の流れ | 所持金不足・売り切れ・在庫上限・品が無い・値段が変わった・カード無し・扱っていない品・クリエイティブ・インベントリ満杯（お釣りが足元に落ちる）。結果コードが正しく、**何も変わらない**こと | A `ServerCases` |
| 画面の値段＝確定の値段 | 仮のプレイヤーに届いたスナップショットから、画面と同じ計算で合計を出して確定する（`trade.priceTolerance` は 0 なので、1c でも違えば断られる）。数量 1・16・64、評判あり、売却も | A `ServerCases`、B `buy_with_screen_buttons`（本物のボタンで買う） |
| 不正な要求 | 要求パケット11種類（取引・まとめて売る・銀行・両替・依頼の受注と納品・輸送依頼・発展・雇い人・掲示板・財布）を、開いている画面と違う市場・無い市場・遠すぎる・画面を開いていない、の4通りで送り、何も変わらないこと。同じ要求を正しく送ると変わることも確かめる（空振りしていない証拠）。数量・金額の 0・負・上限超えも | A `ServerRequestCases`（チェックリスト外。報告にだけ出る） |
| 表示の崩れ | 画面が描く文字の位置と範囲を記録し（テスト用の Mixin `GuiRenderStateMixin`）、同じ層の文字どうしの重なりと、画面・枠からのはみ出し、翻訳されていない文字（この Mod の翻訳キーや `%s` がそのまま描かれたもの）を判定する（`LayoutCheck`。どのケースの判定にも入る）。交易画面の全タブ（掲示板で市場を選んだ状態・依頼と輸送依頼を選んだ状態・発展タブで建物を選んだ状態・「まとめて売る」の枠を開いた状態・カードを持っていて支払いのボタンがある状態も）を、日本語と英語、854×480 と 1920×1080、GUIの大きさ 1〜4 で。設定画面の全タブ（タイトル画面から）と「追加の商品と消耗品」画面の3つのモード（ワールドの中で）を、日本語と英語、854×480 と 1920×1080 で | B `layout_market_screen_ja` / `_en`・`layout_config_screen`・`layout_goods_manager` |
| 文字の色 | 記録した文字の色（品不足のオレンジ、売り切れ・買取停止の赤、▲の赤）で判定する。ツールチップの行の色（`withColor`）は `styleColor` で（流行の人気は赤・余り気味は緑） | B `row_states`・`price_arrows`・`title_reputation_trends` |
| ツールチップ | マウスを乗せて出たツールチップの行（記録した文字のうち画面の層より上のもの）の中身と、画面からはみ出さないこと。価格グラフ（ツールチップと同じく画面の上に描く）は文字の中身で見分け、カーソルの左にあってツールチップの行に重ならないこと | B `ClientDisplayCases`（`tip`）・`debug_tooltip` |
| スクロールバー | 一覧（購入・依頼・掲示板・掲示板の市場の商品・「まとめて売る」）の溝とつまみの位置を画面の内部の値から読み、ホイールで1行・溝のクリックで1ページ・つまみのドラッグで最後まで動くこと、入りきる一覧は動かないこと、行の文字がバーに重ならないこと | B `list_scrollbars`（`ClientScreenCases`） |
| チャット | 自分のチャットに出た行（`Hud.getChat()` の `allMessages`）の翻訳キー・引数・クリックの動作（座標のコピー） | B `map_coordinates_to_chat` |
| ログの監視 | 実行ログに本 Mod に関係するエラー（とロガー `TradeExpansion` の警告）が出たら失敗にする | `record.js`（`log_has_no_mod_errors`） |

## テストを書く時の注意

- A のテストは1つのゲームテストの中で順に実行する（同じバッチのゲームテストは同時に動き、市場はワールド全体で共有されるため）。各項目の後で、市場・商会・雇い人・ブロック・エンティティ・仮のプレイヤー・強制読み込みのチャンクを片付け、設定を既定に戻す
- Minecraft 標準の仮のプレイヤーはクリエイティブ固定なので、A ではサバイバルの仮プレイヤーを自分で作る（`ServerCtx.player`）。その通信路に残るパケットをそのまま読める（`sent`・`messages`・`lastTradeResult`・`lastSnapshot`）。サーバーは flush せずに書くことがある（コマンドの処理の後など）ので、`sent` は読む前に通信路を flush する
- 商会の動き（23章、`ServerReputationCases`）は `rivals.chancePerDay` を 0 にして偶然の動きを止め、テストの中で `Campaign` を作って今日の分を各市場に足す（`rivals start` と同じ処理。商品・向き・強さを決めるため）。ワールドの保存（23-8・24-8）は `MarketRegistry.CODEC` で NBT に書き出して読み直し、比べる
- 村の数が前のテストの村人で1人多く数えられ、「ベッドより村人が多い」で市場が作れないことがある。遠くの市場を作るテストでは `market.newMarketEnoughBeds` を 3 にする
- 村人・行商人との取引（12章、`ServerWorldCases`）は本物の取引画面で行う：`player.interactOn` で開き、`setSelectionHint`＋`tryMoveItems` で取引を選び（選んだ時のパケットと同じ）、`clicked`（`PICKUP`・`QUICK_MOVE`）で結果を取る。村人は `setNoAi` で動かさない
- 設定でレシピの有無が変わる項目（8-3b）は、`server.reloadResources` の完了を待ってから確かめ、最後に設定を戻してもう一度読み直す
- 標準の `placeAt`・`useBlock` はクリックする位置がずれるので、`ServerCtx.click`（`gameMode.useItemOn`）を使う。手に持たせる時は空いている枠を選ぶ（`emptyHand`。初めの所持金のコインを上書きしない）
- テストの区画から離れた場所は、床を敷く時にチャンクを強制読み込みにする（そうしないと、出した村人が数えられない）
- ネザー・エンドの市場（`ServerDimensionCases`）は、`ServerCtx.floor(level, pos)` で石の部屋（床・壁・天井。中は空気）を作り、村人だけを出す（ベッドは爆発する所なので数えない）。ネザーの部屋はテストの区画の座標の 1/8 の位置（y=80）に作り、テストの区画の市場と相場が連動する。エンドの部屋は本島と外の島の間（300, 80, 300）。仮のプレイヤーは `ctx.player(level, pos)` でその次元に出す。別の次元へ移る時は `teleportTo(level, …)`。モブを倒す時は、倒すプレイヤーが同じ次元にいないとプレイヤーが倒した扱いにならない
- 村の建物を建てるテスト（22章、`ServerDevelopmentCases.town`）は、屋台の周りに約73×73の石の床を敷いてから市場を作る（場所探しが平らな地面を見つけられるように）。建物は床の上の片付けの高さより高いので、`cleanUp` が建物の範囲も消す。建て直して前の建物が残る時は `ServerCtx.clearAfter` で消す範囲に足す。資材は `requireMaterials` を OFF にし、評判と発展度はコマンドで足す。完成は `development complete`
- 建物の効果のテスト（28・29章、`ServerFacilityCases`）は `town` で建てて `development complete` で完成させ、効果は倍率そのもの（評判・発展度の増え方、半減期、商会の重み、運び屋の一覧の `accidentMultiplier`・`travelMultiplier`、輸送依頼の報酬の式）で比べる。市場が2つ要る項目は `townMarkets`（最初の市場の周りに大きな床を敷いてから `ServerChapterCases.markets`）。港は床の一部を深さ2の水にする（`pool`。床より下は片付けで消えないので、ケースの終わりに必ず元に戻す）。杭の向きは、置くプレイヤーの向きの反対（`stakeFacing`）。杭の上の「空間がありません」は葉で作る（浮いた石は、その列の地面として数えられて「平らでない」になる）
- 「何も変わらない」の比較（`fingerprint`）の前に、すべての市場を更新する（相場は触れた時にまとめて更新される）
- 相場の戻りは、値段ではなく圧力 X が半減期どおりに減るかで判定する。半減期は `market.params(good).halfLifeDays()`（消耗品は短い）
- B でマウスを押す時、左ボタンは `InputConstants.MOUSE_BUTTON_LEFT`（26.3 は SDL なので 1。0 は部品に無視される）。マウスを動かしてから1ティック待ってから押す
- B で言語を切り替えたら、再読み込みの完了と読み込み画面（`gui.overlay()`）が消えるのを待つ。撮影と表示の判定の前に進捗の通知（トースト）を消す
- 確率の項目は設定で確率を 1 にする。日数の項目は下の「時間を進めるテスト」のとおり
- 本体のコードにテスト専用の処理は足さない（画面の内部の値はリフレクションで読む）。描画の途中に印を付ける時はテスト用の Mixin を使う（「まとめて売る」の枠は一覧の上に同じ層で描かれるので、`MarketScreenMixin` が枠の描き始めに印を付け、枠の下に隠れた一覧の文字を判定から外す）
- B のチャットは `client.gui.hud.getChat()` の `allMessages`（新しい順の `GuiMessage`）をリフレクションで読む。始める前に `clearMessages(false)` で消しておく
- B で1つのケースが2つの項目を確かめ、2つ目だけ失敗した時は `ClientChecklistTests.AlsoFailed` を投げる（1つ目は成功として記録される）
- B の雇い人タブ（`ClientStaffCases`）は5つのケースが雇い人を引き継いで順に動く（運び屋 → 番頭 → おまかせで上限の3人 → 表示の崩れ）。最後の `staff_layout` が全員を解雇し、設定と評判を戻す。続く `ClientStaffMoreCases` の5つのケース（運び屋の変更 → 番頭の変更と売り切れ → おまかせの運び屋と帰り荷の「引取」 → 港・見張り塔 → 事故）は、それぞれ雇い人のいない状態から始め、雇うのはサーバーで `StaffService.handle` を呼んで行う（ボタンと同じ要求。交易画面を開いておく）。最後の `staff_accident` が設定を戻す。港・見張り塔は `ClientTownCases.facility` でブロックなしの建物（看板だけ）をサーバーで作り、終わったら消す。サーバーは雇い人を1秒ごとに動かすので、番頭の下限を 1c にするのは確かめた後にし、`hurry` の前に今の様子を一度見る。2つ目の市場が要るので、絞って流す時は `placement_hint` も入れる（`-Pautotest.only=placement_hint+staff`）。事故と帰り荷は設定で止め、評判は 300 点にする（150 点ちょうどだと減って「常連」を下回る）。運び屋の往復は `/aktradeex staff hurry` で進め、一覧は `requestList` で頼み直して読む
- B のボタンの文字は、幅から左右 2 ピクセルずつ引いた幅に入らないと流れて一部しか見えない（26.3 の `AbstractButton.TEXT_MARGIN`）。小さいボタンは `FittedButton`（入らない時は縮める）にする。`staff_layout` がボタンの文字の幅も確かめる
- B で完成した建物をサーバーで直接作る時（`ClientBankQuestCases.bankTabByLevel`）は、`Facility.complete(core)` の core に施設の看板（`ModBlocks.FACILITY_SIGN`）を置く。看板が無いと、次に市場に触れた時に「壊れた」扱いになる
- B の発展タブ（`ClientTownCases`）は、建物をサーバーで直接作る（`Facility.start`、完成は看板を置いて `complete`、壊れたのは `destroy`）。建てる流れ・ブロックは A で確かめている。看板を右クリックするテストは、看板をプレイヤーの手の届く所に、視線が重ならないように置く
- B で3つ目の市場が要る時（`ClientBoardCases.marketList`）は、遠くの村（ベッドと村人を2組）のチャンクを強制読み込みにし、少し待ってから屋台のブロックを置いて `MarketStallBlockEntity.assign` で市場を作る。強制読み込みにしないと村人が数えられず、市場が作れない。最後に屋台を消して `MarketRegistry.remove` する
- B の流行の倍率は、市場に触れるたびに期間の中で少しずつ動く。決まった値（1.3 など）と比べず、比べる直前のサーバーの値から期待値を出す
- B の「まとめて売る」の枠は、開いている間に新しいスナップショットが届くと金額を計算し直す。別のプレイヤーが売っても枠がすぐ最新になるので、「価格が変動しました」を見る時は、サーバーで相場を直接変えて（スナップショットを送らずに）確定する
- B で依頼・輸送依頼を確かめる時は、サーバーで `market.requests()` の先頭に決まった依頼を足す（ワールドの依頼は実行ごとに変わる）。ほかの人が受けた輸送依頼は、`accepted` に別の UUID を入れて作る
- B で別のプレイヤーの取引を見る時（`ClientBuySellCases.otherPlayerBuys`）は、サーバーに2人目の `ServerPlayer`（`EmbeddedChannel` の接続、A の `ServerCtx` と同じ作り）を足し、`MarketAccess.open` で同じ屋台の画面を開いて `TradeService.handle` で買わせる。終わったら `PlayerList.remove` で外す
- B で所持金を足す時は、足りない時だけにする（100万c ごとにホットバーがコインで1枠埋まり、後の「まとめて売る」のケースが空きを探せなくなる）。財布やコインを入れ替えるケースは、始める前の持ち物を写して最後に戻す（`ClientBuySellCases.saveInventory`）
- B で Mod Menu の画面を見る時（`ClientItemCases.modList`）は、テストのソースセットが Mod Menu の型を参照できないので、`ModsScreen` をリフレクションで開き、検索欄（`searchBox`）に文字を入れて行（`modList` の `children`）を探す。アイコンは行の `getIconTexture()` が Mod Menu の `UNKNOWN_ICON` でないことで見る
- B でクリエイティブタブを開く時（`ClientItemCases.creativeTab`）は、Fabric がこの Mod のタブを2ページ目以降に置くので、`FabricCreativeModeInventoryScreen.switchToPage` でそのページにしてからタブをクリックする（`selectTab` をリフレクションで直接呼んだ時は、ほかのページのタブは選ばれなかった）
- B でアイテムのツールチップを見る時は、インベントリの画面（E キー）でスロットにマウスを乗せ、描かれた文字に行があるかで見る（ツールチップの行が画面の文字より多いと `baseStratum` がツールチップの層になるので、`tooltip()` では分けない）
- B のケースは画面を `setScreen(null)` で閉じるが、これはサーバーに伝わらない。サーバーは最後の交易画面のメニューが開いていると思っていて、持ち物を変えても E キーのインベントリに届かない。サーバーで持ち物を変えてからインベントリを見るケースは、先にサーバーで `closeContainer()` を呼ぶ（`ClientItemCases.fill`）
- B で評判の段階を確かめる時は、境目より少し多くする（評判は時間で減るので、400 ちょうどは数ティックで「常連」に戻る）
- B で YACL の型を使うケースは `ClientConfigCases` に置く。Mod Menu・YACL なしの実行（B′）でも `ClientChecklistTests` を読み込めるように、そこから YACL の型（catch の型も）を参照しない
- B の専用サーバー（`worldBuilder().createServer()`）は同じプロセスの中で動くので、設定（`TradeExpansionConfig` の static）はクライアントと共有になる。「サーバーと自分の設定が違う時」を確かめる 35章は B ではできない（手で確かめる）
- B の設定画面のケースは、始める前に設定ファイルを読んでおき、終わったら書き戻して読み直す（シングルでは内蔵サーバーも読み直す）
- 投稿用の撮影で、世界を作った後に描画距離を変えると、`waitForChunksRender` が終わらなくなる（内蔵サーバーの見える距離は起動時に決まる）。描画距離は世界を作る前に決める。1920×1080 ではマウスの位置が GUI の座標と少しずれることがあるので、ゲームが読んだ位置を見て合わせる（`PostScreenshots.hoverAt`）
- `autotest.bat` に `-Pautotest.only=…` を渡す時は、`=` で引数が分かれるので引用符で囲む。PowerShell の `--%` だと後ろのリダイレクトまで渡ってしまうので、引数を受ける小さな .bat を作って呼ぶのが確実

## 時間を進めるテスト

依頼の期限・品不足の入れ替わりなど、日がたつ必要があるテストは、`/aktradeex clock advance <日数>`（すべての市場の時計を進める。13-10 のテストで使っている）で進められる。それより前に書いたテストは、市場を作る前に設定 `recovery.clock` を `DAY_TIME` にし（`ServerChapterCases.dayClock`）、`/time add` で昼夜の時計を進めている（`addDays`）。新しく書くテストは `clock advance` を使う（設定を変えずに済む）。`market advance` は相場と在庫の回復しか進めない。

ワールドは実行のたびに変わる（市場の品揃え・依頼・品不足・ばらつき）。たまたま合う品に頼らないこと：値段が 1c 動くのに必要な数を計算して売り買いする（安い品は数個では動かない）、評判の値引きは品ごとの上限で 0 になる品がある、★3の依頼には評判が要る、2つの市場に共通の品が無いことがある（`ServerChapterCases.shared` は無ければ足す）。足したテストは `gradlew runGameTest` を何回か続けて流して確かめる。

遠く（600 ブロックなど）の市場を初めて使うと、強制読み込みしたチャンクの生き物が読み込まれるまで時間がかかる。その前に出した村人は消える（後のテストに現れることもある）。`ServerChapterCases.markets` は読み込みを待ってから村を作る。

入り直し（`ServerCtx.rejoin`）は同じプロフィールでもう一度入らせる。ワールドごとの保存（初めの所持金を受け取った人など）と進捗は引き継がれるが、仮のプレイヤー自身の保存データ（持ち物）は読み直されない。生き返り（`ServerCtx.respawn`）の後の仮のプレイヤーは、テストのワールドでは遠くの出現地点に送られ、そこから動かせないので、生き返った後に取引するテストは書けない（引き継がれたデータを直接確かめる）。

仮のプレイヤーは「クライアントの読み込みが済んだ」合図（`ServerboundPlayerLoadedPacket`）を送らないので、そのままでは傷つかない。死ぬ必要があるテストでは `ServerChapterCases.clientLoaded` で済ませた扱いにする。
