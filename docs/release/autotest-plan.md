# ゲーム内チェックリストの自動化の方針

`ingame-checklist.md` の項目を、どの方法で確かめるかの対応表です。自動テストを足したら、ここの表も直します。

## 方法

| 記号 | 方法 | 実行 | 判定 |
|---|---|---|---|
| A | サーバーのテスト（`src/gametest/.../server/`）。画面なしのサーバーで、テストの区画に小さな村（ベッドと村人）を作り、仮のプレイヤーで交易所を置き、取引する | `autotest.bat server`、`build.bat gametest`（約1分） | 自動 |
| B | クライアントのテスト（`src/gametest/.../client/ClientChecklistTests.java`）。本物のクライアントを**日本語**で起動してワールドを作り、キーとマウスで操作する | `autotest.bat client`（ゲームのウィンドウが開く。数分） | 自動 |
| C | B の中でスクリーンショットを撮る（`build/autotest/screenshots/`） | B と同じ | 人が画像を見る |
| 手 | 手で確認する（他の Mod・2人のプレイ・遊んだ感触・自然に生成された村など） | ― | 人 |

結果は `tools/checklist/record.js` がチェックリストの各行に書き込みます（全部を確かめた項目は `[x]` と〔自動 ✔ 版 日付〕、一部だけなら〔一部自動 ✔ 版 日付：確かめた範囲〕、失敗は〔自動 ✘ 版 日付：テスト名〕）。一覧は `autotest-report.md` です。

## テストの種類

| 種類 | 内容 | 場所 |
|---|---|---|
| 成功の流れ | 置ける・買える・売れる・値段が動く・レシピなど。所持金・持ち物・相場の変化と、仮のプレイヤーに届いたチャット（翻訳キー）と結果コード（`TradeResultS2C` など）で判定する | A `ServerCases` |
| 失敗の流れ | 所持金不足・売り切れ・在庫上限・品が無い・値段が変わった・カード無し・扱っていない品・クリエイティブ・インベントリ満杯（お釣りが足元に落ちる）。結果コードが正しく、**何も変わらない**こと | A `ServerCases` |
| 画面の値段＝確定の値段 | 仮のプレイヤーに届いたスナップショットから、画面と同じ計算で合計を出して確定する（`trade.priceTolerance` は 0 なので、1c でも違えば断られる）。数量 1・16・64、評判あり、売却も | A `ServerCases`、B `buy_with_screen_buttons`（本物のボタンで買う） |
| 不正な要求 | 要求パケット11種類（取引・まとめて売る・銀行・両替・依頼の受注と納品・輸送依頼・発展・雇い人・掲示板・財布）を、開いている画面と違う市場・無い市場・遠すぎる・画面を開いていない、の4通りで送り、何も変わらないこと。同じ要求を正しく送ると変わることも確かめる（空振りしていない証拠）。数量・金額の 0・負・上限超えも | A `ServerRequestCases`（チェックリスト外。報告にだけ出る） |
| 表示の崩れ | 画面が描く文字の位置と範囲を記録し（テスト用の Mixin `GuiRenderStateMixin`）、同じ層の文字どうしの重なりと、画面・枠からのはみ出しを判定する。交易画面の全タブを、日本語と英語、854×480 と 1920×1080、GUIの大きさ 1〜4 で | B `layout_market_screen_ja` / `_en` |
| ログの監視 | 実行ログに本 Mod に関係するエラー（とロガー `TradeExpansion` の警告）が出たら失敗にする | `record.js`（`log_has_no_mod_errors`） |

## テストを書く時の注意

- A のテストは1つのゲームテストの中で順に実行する（同じバッチのゲームテストは同時に動き、市場はワールド全体で共有されるため）。各項目の後で、市場・商会・雇い人・ブロック・エンティティ・仮のプレイヤー・強制読み込みのチャンクを片付け、設定を既定に戻す
- Minecraft 標準の仮のプレイヤーはクリエイティブ固定なので、A ではサバイバルの仮プレイヤーを自分で作る（`ServerCtx.player`）。その通信路に残るパケットをそのまま読める（`sent`・`messages`・`lastTradeResult`・`lastSnapshot`）
- 標準の `placeAt`・`useBlock` はクリックする位置がずれるので、`ServerCtx.click`（`gameMode.useItemOn`）を使う。手に持たせる時は空いている枠を選ぶ（`emptyHand`。初めの所持金のコインを上書きしない）
- テストの区画から離れた場所は、床を敷く時にチャンクを強制読み込みにする（そうしないと、出した村人が数えられない）
- 「何も変わらない」の比較（`fingerprint`）の前に、すべての市場を更新する（相場は触れた時にまとめて更新される）
- 相場の戻りは、値段ではなく圧力 X が半減期どおりに減るかで判定する。半減期は `market.params(good).halfLifeDays()`（消耗品は短い）
- B でマウスを押す時、左ボタンは `InputConstants.MOUSE_BUTTON_LEFT`（26.3 は SDL なので 1。0 は部品に無視される）。マウスを動かしてから1ティック待ってから押す
- B で言語を切り替えたら、再読み込みの完了と読み込み画面（`gui.overlay()`）が消えるのを待つ。撮影と表示の判定の前に進捗の通知（トースト）を消す
- 確率の項目は設定で確率を 1 にする。日数の項目は市場の時計を `DAY_TIME` にして時刻を進める（予定）
- 本体のコードにテスト専用の処理は足さない（画面の内部の値はリフレクションで読む）

## 自動テストで見つかったこと

- **交易画面の一覧で、在庫の数字が値段に重なる**（チェックリスト 3-6。`MarketScreen.extractRow`）。在庫の上限が128の商品（矢・松明・丸石など）では、在庫が「128/128」でも「48/128」でも重なる。購入・売却の両タブ、日本語・英語、どの画面の大きさでも出ていた。→ 0.2.3 で直した（値段の右端を左に寄せて在庫の欄を広げ、入らない数字は縮める）。表示の崩れのテストが通るようになった
- 取引の要求が断られた時、サーバーは要求に書かれた市場のスナップショットを送り返す。開いている画面と違う市場の ID を書くと、遠くの市場の相場も受け取れた（まとめて売るも同じ）。→ 0.2.3 で、開いている画面の市場の時だけ送るようにした。`request_trade`・`request_sell_all` で確かめている
- 雇い人の一覧・行き先・品の候補（読み取りだけの操作）は、屋台から離れていても返る。お金や品を動かす操作は距離を検証している（仕様どおり）
